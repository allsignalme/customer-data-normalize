# Specification

This library implements three specifications. Each one has a vector file in [`vectors/`](vectors/) that both
implementations (Go and TypeScript) must pass byte for byte.

| Spec | Vector file | Go package | TypeScript module |
|---|---|---|---|
| meta v1 | `vectors/meta-v1.json` | `meta` | `@allsignalme/customer-data-normalize/meta` |
| openai v1 | `vectors/openai-v1.json` | `openai` | `@allsignalme/customer-data-normalize/openai` |
| phone-international v1 | `vectors/phone-international-v1.json` | `phone` | `@allsignalme/customer-data-normalize/phone` |

## Common rules

- **Whitespace** is JavaScript `\s`: U+0009–U+000D, U+0020, U+00A0, U+1680, U+2000–U+200A, U+2028, U+2029, U+202F,
  U+205F, U+3000, U+FEFF. U+0085 and U+200B are not whitespace. **Trim** removes it at both ends.
- **Lowercase** is JavaScript `String.prototype.toLowerCase()`: Unicode full lowercase mapping without locale rules.
  It differs from a simple per-character mapping in two places: `İ` (U+0130) becomes `i` + U+0307, and a capital sigma
  at the end of a word becomes `ς`.
- No Unicode normalization (NFC/NFD) is applied. Send NFC input.
- **Hash** is SHA-256 of the UTF-8 bytes, as 64 lowercase hex characters.
- **Pre-hashed input**: for hashed fields, if the trimmed input is exactly 64 hex characters (either case), it is
  treated as an existing SHA-256 digest: returned lowercased, never hashed again.
- **Dropped value**: Go returns `"", false` (or `""`), TypeScript returns `null`. The caller must not send the field.

## meta v1

Meta Conversions API, `user_data` parameters
([Customer Information Parameters](https://developers.facebook.com/documentation/ads-commerce/conversions-api/parameters/customer-information-parameters)).

**Reference.** Normalization reproduces Meta's own implementation in
[meta/capi-param-builder](https://github.com/meta/capi-param-builder) (Node.js, `src/piiUtil`, commit `08cf920`,
2026-11-05), the same code Meta ships for browsers, so a value hashed by this library equals the value Meta's client
code would hash. The vector file was generated by running that reference; every example with a published hash in
Meta's documentation is included and matches.

**Deviations from the reference**

| Id | Reference | This spec | Why |
|---|---|---|---|
| D1 | Appends `.<appendix>` to each hash | Plain 64-hex digest | The appendix is parameter-builder telemetry; the API accepts plain digests |
| D2 | 32-hex (MD5) values pass through unchanged | Only 64-hex values pass through | A 32-hex string can be a real id (e.g. an `external_id`) |
| D3 | Phone: never adds a country code | With the customer's country, a national number is first converted with phone-international v1 | Meta requires the country code |
| D4 | Date-of-birth year bound uses local time | Uses UTC | Same result on every server |

**Rules per field**

| Key | Rule |
|---|---|
| `em` | Lowercase, trim. Must match the email pattern (ASCII local part; domain with at least one dot). |
| `ph` | (D3 first when a country is given.) Keep digits 0-9 only, remove leading zeros. No length check. |
| `fn`, `ln` | Remove whitespace and ASCII punctuation ``!"#$%&'()*+,-./:;<=>?@[\]^_`{|}~``, then lowercase. Other characters are kept (accents, Hangul, non-ASCII punctuation such as `’`). |
| `db` | Split into groups of digits. With three or more groups, read the first three `n1 n2 n3`: the year is `n1` if > 31, else `n2` if > 31, else `n3`; of the two others the one > 12 is the day, otherwise month comes first. Must be a valid Gregorian date with year 1800 to next year => `YYYYMMDD`. A single group of exactly 8 digits is kept as is (not validated). Anything else is dropped. |
| `ge` | Lowercase, trim, then look up the word lists (`male`, `man`, `mr`, `m`… => `m`; `female`, `woman`, `mrs`, `f`… => `f`). Unknown words are dropped. |
| `ct` | Keep only `a-z A-Z 0-9`, lowercase. Must start with a letter. |
| `st` | Lowercase, trim, keep `a-z`. Two letters are kept as is. Otherwise an exact US state or Canadian province name becomes its code; otherwise the first table name contained in the value (Canadian provinces, then US states, in table order) becomes its code. Then cut to two letters. Empty is dropped. |
| `zp` | Lowercase, keep the part before the first `-`, trim. At least 2 characters. |
| `country` | Same as `st` with the country name table (ISO 3166-1 names and common aliases). |
| `external_id` | Remove whitespace, lowercase. |

The lookup tables (states, provinces, countries, gender words) are in [`data/meta-tables.json`](data/meta-tables.json),
extracted from the reference; `scripts/gen-tables.mjs` generates the Go and TypeScript tables from it.

**Where Meta's documentation and the reference disagree, this spec follows the reference:** `ct` drops non-ASCII
letters (`Hà Nội` => `hni`); `st` outside the US is cut to two letters (`Bavaria` => `ba`); `zp` keeps inner spaces and
drops everything after a dash (`M1 1AE` => `m1 1ae`, `100-0001` => `100`); `ph` gets a country code only through D3.
Changing any of these is a new spec version.

**Never hashed:** `client_ip_address`, `client_user_agent`, `fbc`, `fbp`, `subscription_id`, `fb_login_id`, `lead_id`,
`anon_id`, `madid`, `page_id`, `page_scoped_user_id`, `ctwa_clid`, `ig_account_id`, `ig_sid`. `ShouldHash` /
`shouldHash` returns true only for the eleven keys in the table above.

## openai v1

OpenAI Conversions API identifiers. Matches the OpenAI browser SDK (`oaiq` v0.1.41), so the browser and the server
produce the same value.

| Kind | Rule | Hashed |
|---|---|---|
| `email` | Trim, lowercase. At most 254 characters; must match the email pattern. | yes |
| `phone` | Remove whitespace and `( ) . -`. The rest must be digits with an optional leading `+`, and not `+0`. Remove the `+` and all leading zeros. With an international prefix (`+` or `00`), a number starting with 1 must have exactly 11 digits (North America). 8 to 15 digits. No country code is added: run phone-international first for address phones. | yes |
| `first_name`, `last_name` | At most 1024 characters (UTF-16). Remove whitespace and ASCII punctuation, lowercase. Must contain at least one non-digit. | yes |
| `external_id` | Trim only; case is kept. | yes |
| `city`, `region` | Lowercase, collapse whitespace runs to one space, trim. 1 to 128 characters. | no, sent in clear |
| `postal_code` | As `city`, then only `a-z 0-9`, space and `-`; at most 31 characters. | no |
| `country` | As `city`, then exactly two letters `a-z`. | no |

The API uses only the first three valid values of each array; `AppendIdentifier` / `appendIdentifier` keeps the first
three unique hashes.

## phone-international v1

Converts a phone number taken from an address (often in national format, `0983 714 965`) to international format
using the country of that same address. It runs before phone normalization. It converts only when the result is
certain; otherwise it returns nothing, because a hash of a wrong number is worse than no number.

1. Trim; empty => none. A number starting with `+` or `00` is returned unchanged.
2. Remove whitespace and `( ) . -`. Any other non-digit, or a missing country => none. The country is trimmed and
   uppercased (ISO 3166-1 alpha-2).
3. North America (`US`, `CA`, `PR`): 10 digits => `+1` + digits; 11 digits starting with 1 => `+` + digits; otherwise
   none.
4. Countries with trunk prefix 0 (`VN TH ID MY PH JP KR CN TW IN PK BD LK AU NZ GB IE FR DE NL BE AT CH SE FI TR IL AE SA
   EG ZA NG KE UA`): a number starting with 0 => `+<calling code>` + the number without that 0. `RU`, `KZ` (trunk
   prefix 8): starting with 8 => `+7` + the number without that 8. No trunk prefix => none.
5. Any other country => none.

## Versioning

- A spec version is frozen once released: the same input always gives the same output.
- Any change of output for any input (a rule, a table entry, a bug fix that changes a result) creates a new spec
  version with its own vector file, and a new major version of the library. Hash values stored or sent under the old
  version stay comparable only with that version.
- Go and TypeScript must agree on every vector. A disagreement is a bug in the implementation, not in the spec.
